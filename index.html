Three names, three different things

VS Code
The program you actually type code into. It's what you install first, and everything else plugs into it.
Git
A program that runs on your laptop. It takes snapshots of your files so you can go back to any earlier version. It has no website and no login.
GitHub
A website that stores a copy of those snapshots online, so other people can see your work and you have a backup. Owned by Microsoft, free for what you're doing.

Git and GitHub are separate things with confusingly similar names. You need both, and you install them at different points below.

Part 01≈ 10 minutes

Install VS Code

Visual Studio Code is the window you write in. It's free, and it is not the same thing as "Visual Studio" — if the download is several gigabytes, you're on the wrong page.

On Windows

  1. Go to code.visualstudio.com/download and click the Windows button. You'll get a file ending in .exe.

  2. Run it. Accept the agreement and click through the first few screens.

  3. On the screen headed Select Additional Tasks, tick these boxes:

    Add "Open with Code" action to Windows Explorer file context menu · Add "Open with Code" action to Windows Explorer directory context menu · Add to PATH

    The PATH box is the one that matters. It's ticked by default — leave it ticked.

  4. Finish the installer and let it open VS Code.

On Mac

  1. Go to code.visualstudio.com/download and click the Mac button. Pick Apple Silicon if your Mac is from 2021 or later, Intel if it's older. Universal works on either if you're unsure.

  2. Your browser downloads a .zip and usually unzips it for you, leaving Visual Studio Code in your Downloads folder.

  3. Drag Visual Studio Code into your Applications folder. This step is easy to forget and everything works better once you do it.

  4. Open it from Applications.

    If macOS says it can't verify the developer, close the message, right-click the app icon, choose Open, and confirm. You only do this once.

  5. Right-click the VS Code icon in your Dock and choose Options → Keep in Dock.

How you know it worked

VS Code opens and shows a Welcome tab. There's a vertical strip of icons down the left edge — that strip is called the Activity Bar, and you'll be clicking things on it for the rest of this guide.

Learn the left strip now — you'll use it constantly

Every instruction below says things like "click Extensions" or "click Source Control". Those are all icons on this one strip. Here is what each is, top to bottom. The four in green are the ones this guide uses.

Part 02≈ 20 minutes

Your first project, and Codex

Codex is OpenAI's coding assistant, and it runs on the ChatGPT account you already pay for — no API key, no separate card, no developer account. It won't start without a project folder to look at, so you make one first.

Make a folder and open it

  1. Make an ordinary folder somewhere sensible — Documents, say — and call it hello-cs.

  2. In VS Code: File → Open Folder (on some versions it's File → Open…) and choose that folder.

    If VS Code asks whether you trust the authors of the files in this folder, say yes. It's your folder.

  3. Make a file. File → New File, type a line or two, then save it as hello.py (or index.html — anything).

    Save it properly with Ctrl⌘ S. A dot beside the tab name means unsaved.

Check you opened a folder, not a file

A file is one document — hello.py. A folder is the box that holds documents — hello-cs. VS Code can open either, and it looks almost the same, but only one of them works. Codex won't start without a folder, and neither will the version control in Part 5.

If you're looking at the right-hand one Go back to File → Open Folder and pick hello-cs itself — click the folder once to select it, then click Open. Don't go into the folder and pick the file inside it. That one distinction causes more stuck beginners than anything else in this guide.

Install Codex

  1. Click Extensions in the left icon strip — the four squares with one pulled away from the others.

  2. Search for Codex and install the one published by OpenAI.

    Several look-alikes share the name. The right one is identified as openai.chatgpt on its detail page. If you'd rather not guess, install it from the marketplace listing.

  3. Look at the left strip again. A new icon has appeared on it that wasn't there before — that's Codex. Click it.

    If you can't find it, press Ctrl⌘ Shift P and type Codex: Open Codex Sidebar.

  4. Choose Sign in with ChatGPT. Your browser opens, you approve, and VS Code comes back to the front.

  5. If a box appears asking you to add a project, pick your hello-cs folder and click Add project.

How you know it worked

The Codex panel shows a message box instead of a sign-in button, and the status bar at the bottom shows your project name. Type what files are in this project? and it answers with your actual file names.

For now: ask, don't let it edit

Until Part 5, use Codex to explain things, not to change your files. Ask it what does this line do?, why is this an IndentationError?, what's a sensible name for this variable? — and read the answers.

The reason is simple: right now there is no undo. If it rewrites a file and you don't like the result, nothing on your laptop remembers what the file looked like before. Part 5 fixes that, and then you can let it loose.

If Codex says "Add a project to use Codex"

It has no folder. Go back to File → Open Folder and pick hello-cs. Don't point it at your whole home directory or the root of your hard drive — it wants one project.

If sign-in fails with "403" or "contact your administrator"

Your ChatGPT account belongs to an organization workspace, and Codex is controlled by a setting an administrator holds. They toggle it under workspace settings; you can't turn it on yourself.

This is worth checking before a workshop rather than during one. If it's blocked, everything else on this page still works — skip to Part 3 and use the ChatGPT tab as your assistant instead.

Worth saying out loud to a class Codex is fluent and sometimes wrong in the same breath. It produces code that runs but doesn't do what you asked, cites functions that don't exist, and never signals uncertainty. Treat every suggestion as a draft from a confident stranger.
Part 03≈ 10 minutes

Make a GitHub account

This is the account whose name ends up in every link you share, so it's worth spending two minutes on the username. Codex can't see your browser, so if you get stuck here, the ChatGPT tab is the one to ask.

  1. Go to github.com/signup.

  2. Enter an email address you'll still have in three years.

    A university address works and later qualifies you for GitHub Education benefits. You can add a second email to the account afterwards.

  3. Create a password. GitHub requires at least 15 characters, or at least 8 if it includes a number and a lowercase letter.

  4. Pick a username. This becomes part of every address you hand out — github.com/yourname/project-name.

    Lowercase, no graduation year, nothing you'd be embarrassed to put on a résumé. Changing it later breaks every link you've already shared.

  5. Solve the puzzle, then type in the code GitHub emails you.

  6. When asked to choose a plan, choose Free. It includes unlimited public and private repositories.

  7. Set up two-factor authentication when prompted. GitHub requires it for anyone who uploads code, so you can't skip it for long.

    An authenticator app (Microsoft Authenticator, Google Authenticator, Authy) is faster than text messages. Save the recovery codes it shows you — put them somewhere that isn't your phone.

How you know it worked

Type github.com/your-username into your browser and you see your own profile page, empty except for your name.

Part 04≈ 10 minutes

Install Git — the step people skip

VS Code's version-control buttons don't do the work themselves; they hand it to Git. If Git isn't installed, the buttons either don't appear or don't respond, and there's no error message explaining why. Nearly every "it's broken" moment in a first workshop traces back to here.

On Windows

  1. Go to git-scm.com/download/win. The download starts on its own; if it doesn't, click 64-bit Git for Windows Setup.

  2. Run the installer. It asks a lot of questions — the defaults are all correct. Click Next through them.

    The one screen worth a glance asks which editor Git should use. Choose Use Visual Studio Code as Git's default editor if you like; nothing breaks either way.

  3. Click Install, then Finish. Untick "View Release Notes".

  4. Close VS Code completely and reopen it, then reopen your hello-cs folder. VS Code only looks for Git when it starts up.

On Mac

  1. In VS Code, open the menu Terminal → New Terminal. A panel opens at the bottom of the window.

  2. Type this and press Enter:

    git --version

  3. If a version number appears, Git is already installed — skip ahead to naming yourself.

    If a box pops up offering to install the command line developer tools, click Install and wait. It's a few hundred megabytes.

    If neither happens, download the installer from git-scm.com/download/mac.

  4. Quit VS Code completely (⌘ Q — closing the window isn't enough on a Mac) and reopen it, then reopen your hello-cs folder.

Then tell Git who you are

You do this once, ever. Git stamps your name and email onto every snapshot, and GitHub uses the email to credit the work to your account.

Open Terminal → New Terminal in VS Code and type these two lines, pressing Enter after each, with your own details swapped in:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Use the same email Use the exact address on your GitHub account from Part 3. If it doesn't match, your commits show up on GitHub as an anonymous grey silhouette instead of you.
How you know it worked

In the VS Code terminal, git --version prints something like git version 2.51.0, and git config --global user.name prints your name back at you.

Part 05≈ 20 minutes

Connect VS Code to GitHub

You sign in once, take your first snapshot, and put the folder online. After this you never type a GitHub password again — and Codex gets to start editing.

Watch: How to Connect GitHub to Visual Studio CodeSaad Qureshi Official · the same steps, on screen

Sign in

  1. In VS Code, look at the bottom of the left icon strip for the person-shaped Accounts icon, below the gap. Click it.

  2. Choose Sign in with GitHub.

  3. Your browser opens. Sign in to GitHub if it asks, then click the green Authorize Visual-Studio-Code button.

  4. The browser asks whether to open Visual Studio Code. Say yes. VS Code comes back to the front.

How you know it worked

Click the Accounts icon again. Your GitHub username is listed there.

Take your first snapshot and publish it

  1. With hello-cs open, click Source Control in the left icon strip — the branching line. Keyboard: Ctrl⌃ Shift G.

  2. Click Initialize Repository.

    You've just told Git to start taking snapshots of this folder. Nothing has left your laptop yet.

  3. Your file appears under Changes. Hover over its name and click the + that appears. It moves up to Staged Changes.

    Staging is you saying "these are the edits I mean to record" — it lets you save a snapshot of some changes and not others.

  4. Type a short message in the box at the top — first commit — and click the blue Commit button.

    That's a snapshot. It lives on your laptop and you can return to it forever.

  5. Click the blue button that replaces it, labelled Publish Branch — some versions say Publish to GitHub. Same thing.

  6. VS Code asks whether to publish to a private or public repository. Private means only you and people you invite can see it; you can switch it to public any time.

How you know it worked

A small notification offers Open on GitHub. Click it. Your file is sitting on a web page with your username in the address. That address is the thing you share.

Now let Codex edit

You have an undo button, so the rule from Part 2 lifts. Try this once, deliberately, so you see the mechanism:

  1. Ask Codex to change something real — add comments to this file explaining each line to a beginner.

  2. When it's done, open Source Control and click the file name.

    VS Code shows the before and after side by side, in green and red. Every line it touched is visible.

  3. Don't like it? Hover the file in the Changes list and click the ↺ (Discard Changes). The file snaps back to your last commit as if nothing happened.

  4. Like it? Stage, commit, and say so in the message — added comments (Codex). Future you will want to know which parts you wrote.

The habit worth teaching above all others

Commit before you let it edit. Not because Codex is untrustworthy in particular, but because a snapshot turns every AI suggestion from a gamble into a proposal you can read and reject.

This is also the most convincing argument for version control you will ever have in front of a class. They've just spent twenty minutes wanting an undo button. Now they have one, and they know exactly what it's for.

From now on, every session is this loop
  1. Edit your files and save them.
  2. Open Source Control, click + to stage what you changed.
  3. Type a message describing what you did.
  4. Click Commit.
  5. Click Sync Changes — this sends yours up and pulls anyone else's down.

Five words your students will need

Repository (repo)
A folder Git is watching. It exists twice: on your laptop and on GitHub.
Commit
One saved snapshot, with a message attached saying what changed and why.
Stage
Choosing which changes go into the next commit. This is the step nobody expects.
Push / pull
Push sends your commits up to GitHub. Pull brings other people's down. Sync does both.
Clone
Downloading a repository from GitHub to a laptop, history and all.
Part 06≈ 10 minutes

Share your code

The link is simply the address bar. Everything below is about who can open it.

Watch: How To Share a Link To a GitHub RepositoryThe 60-second version of this part

The whole project

  1. Open your repository on github.com and copy the address from your browser's address bar. It looks like github.com/yourname/hello-cs.

  2. Paste it into an email, a syllabus, or your LMS. That's the entire mechanism.

The one that catches everyone If you made the repository private, that link shows a 404 to everyone else — it doesn't say "no permission", it says the page doesn't exist. Either make it public, or invite people by name.

Making it public, or inviting people

  1. To make it public: on the repository page, Settings → scroll to the bottom → Change visibility → Public.

  2. To invite specific people: Settings → Collaborators → Add people → type their GitHub username. They get an email invitation they have to accept.

Sharing something narrower

  1. One file: click it on GitHub and copy the address.

  2. Specific lines: open the file, click the line number in the left margin, shift-click a second line number to select a range, then copy the address. It now points at exactly those lines — useful for "look at line 14".

  3. A starting point for students: Settings → tick Template repository. Everyone who opens your repo gets a Use this template button that hands them their own private copy.

  4. Someone else's code onto your laptop: in VS Code, open Source Control with no folder open and click Clone Repository, then paste their address.

How you know it worked

Open the link in a private or incognito browser window, where you aren't signed in. If you can read it there, so can whoever you send it to.

Reference

When it breaks

The things that actually go wrong, in rough order of frequency. Paste any of these into your ChatGPT tab if the fix here doesn't land.

Add a project to use Codex
No folder is open, or you opened a single file. File → Open Folder and pick your project — not your home directory, not the root of the drive.
Codex: 403 Unauthorized / contact your administrator
Your ChatGPT account is in an organization workspace where an admin controls Codex access. They have to switch it on; you can't. Everything else in this guide still works.
'git' is not recognized / command not found
Git isn't installed, or it is and VS Code hasn't been restarted since. Go back to Part 4 and quit VS Code fully — closing the window isn't enough on a Mac.
Source Control panel is blank
No folder is open. File → Open Folder, not File → Open File.
Nothing appears under Changes
The file isn't saved. Ctrl⌘ S. A dot beside a tab name means unsaved.
Updates were rejected / push failed
Someone changed the GitHub copy since you last looked. Click Sync Changes to pull theirs in first, then push again.
It's asking for a GitHub username and password
GitHub stopped accepting account passwords for this years ago. Cancel, click the Accounts icon at the bottom left, and sign in with GitHub properly.
Codex rewrote something and I want it back
If you've committed at least once: Source Control → hover the file → click ↺ Discard Changes. If you haven't committed yet, that's the lesson — commit first next time.
If your school laptop won't let you install anything

There's a browser-only path that requires no installation at all. Open any repository on GitHub and press the . key — a full VS Code opens in the browser tab, editing that repository directly. Commits work; the terminal doesn't.

For a version that can actually run code, use GitHub Codespaces, which gives a free monthly allowance of hours on a personal account. Both are worth knowing about as a fallback for a classroom set of locked-down machines.

Running this as a workshop: what to check beforehand

Codex access. If your ChatGPT plan is an organization one, confirm with whoever administers it that Codex is enabled for members. A room discovering a 403 together at minute twenty is a bad twenty minutes.

Install permissions. Parts 1 and 4 both install software. Find out in advance whether the machines allow it, and have the browser-only fallback above ready if not.

Timing. Parts 1 and 2 get everyone to a working editor with an assistant in about half an hour — a natural place to break. Parts 3 through 6 are the version control half and run about forty-five minutes.

Written for people who have never used any of these tools. Steps and menu names reflect current versions as of September 2026; VS Code updates monthly, so a button occasionally moves.
